# InklingMD v3.0.0 设计文档

> 发布日期：2026-09-05
> 版本性质：**主版本质量攻坚**（无新功能，全部投入可靠性）
> 覆盖范围：45 个 GitHub Issues（#146–#188、#192、#200）+ 19 个 PR（#189–#211），61 个代码提交、113 个文件（+8486 / −722，不含发版文档提交）
> 质量门禁：Vitest 115 文件 / 745 用例、Playwright E2E 169 用例、Rust `cargo test` 59 用例（Windows；ubuntu 55，4 个 `#[cfg(windows)]` 用例不参与编译）、`tsc --noEmit` 零错误、CI 双平台全绿

---

## 1. 版本定位

v2.8.1 之后累积了一批由真实使用暴露出来的缺陷，其分布高度集中：**文件操作的原子性缺口、并发/时序竞态、崩溃兜底过激、大依赖启动加载、以及系统性的可访问性缺失**。这些问题单看是独立 bug，合并看指向同一个结论——应用在「异常路径」上的行为缺乏统一设计。

v3.0.0 因此跳到主版本号：**不新增功能，把异常路径当作一等公民重新设计**。所有修复遵循三条共同原则：

1. **失败要留下完整的数据**（宁可报错保留原件，不做「先删后建」的赌博）。
2. **状态按最小粒度隔离**（保存、退避、冲突都从「工作区级」下沉到「标签页 / 文件级」）。
3. **降级只针对真失败**（慢启动不等于失败，良性错误不等于崩溃）。

## 2. 数据安全：文件操作的原子性与 TOCTOU 治理

涉及 issue：#146、#161、#159、#166、#177、#200

### 2.1 #146 Windows 写入回退路径非原子

**根因**：原子替换（临时文件 → `rename`）失败后的回退分支采用「先删目标再 rename」。这两步之间若进程被杀或系统崩溃，文件即处于**已删未建**状态——原内容与新内容同时丢失。

**方案**：引入 `replace_file_with_retry`，改为最多 4 次 × 50ms 退避的原子替换重试。全部失败则**保留原文件并返回错误**，绝不进入中间态。

**验证**：3 例 Rust 单测——可替换成功、目标被独占占用时保留原件、临时文件缺失时保留原件。

### 2.2 #161 跨盘移动失败 + 目标存在性检查 TOCTOU

**根因**：两处独立缺陷。

- `rename_path` 依赖 `fs::rename`，跨卷时返回 `ERROR_NOT_SAME_DEVICE` / `EXDEV` 直接失败，不支持跨盘移动。
- 目标存在性检查是「先 `exists()` 再 `fs::rename`」的两步式，中间存在**目标被并发创建后静默覆盖**的 TOCTOU 窗口。

**方案**：

- **闭合 TOCTOU**：文件移动优先走「硬链接 + 删源」。硬链接的创建本身是原子的——目标已存在时以 `AlreadyExists` 原子失败，从而消灭「检查」与「占用」之间的时间差。硬链接跨卷 / 文件系统不支持时回落到原路径。
- **跨卷回退**：`fs::rename` 跨卷失败时改为**递归目录复制 + 删源**；复制失败时源原件保持完整，已产生的文件残块尽力清理，不再把裸 OS 错误抛给用户。

### 2.3 #159 读取编码错误生硬 + 无大小上限

**方案**：

- **大小护栏**：先读元数据判断，超过 10MB 直接拒绝（打开场景比搜索侧的 5MB 放宽），防止数百 MB 文件整体读入内存并经 JSON IPC 传输。
- **结构化错误**：非 UTF-8 与超限场景返回 `ENCODING_UNSUPPORTED` / `FILE_TOO_LARGE` 标记，前端可据此给出可读提示，而非把 `FromUtf8Error` 原始文本呈现给用户。

### 2.4 #166 / #177 / #200 读取与重命名的竞态收敛

三处是同一条链路上逐步暴露的时序问题：

- **#166**：删除文件快照的两处竞态——快照早于序列化防抖发布采集、在途读取在删除后生成漏网 tab。
- **#177**：重命名与在途文件读取竞态，重开文件可能拿到陈旧内容、加载状态永久卡死。
- **#200**：#177 修复后的已知边界——读取在途时重命名，完成后 `ensureTab` 仍按**旧路径**创建幽灵 tab。

**方案**：读取完成后按**当前（落定）路径**归属 tab；共享在途请求的「加入方」同样拿到落定路径，避免并发场景下幽灵 tab 与黑名单漏拦。

## 3. 保存与冲突链路：从「工作区级」下沉到「标签页级」

涉及 issue：#148、#149、#164、#170、#186

### 3.1 #148 全局 saving 标志按整个工作区生效

**根因**：`saving` 是工作区级全局标志。任一保存挂在另存为 / 冲突对话框期间，其他标签页的保存请求被**静默吞掉**——用户以为已保存，实际没有。

**方案**：`OpenTab` 各自持有 `saving`，`saveCurrent` 只拦本 tab 重入；`switchTab` / 写盘完成 / 异常路径的顶层 `saving` 镜像统一从活跃 tab 派生，保持对外接口语义不变。

### 3.2 #149 自动保存遇非交互冲突后无限 2s 重试

**根因**：冲突处于「非交互」（等待用户决策）状态时，自动保存仍每 2 秒全量读盘重试——无退避、无错误态展示、且每轮读盘放大 I/O。

**方案**：

- `conflictPending` 期间**暂停自动保存**，消除空转。
- 失败退避计数 `failCount` **按文件隔离**——A 文件的失败不再拖慢 B 文件的保存节奏。

### 3.3 #164 conflictPending 冲突解决后不清除

**方案**：`reloadFile` 统一清除 tab 与镜像的 `conflictPending`，使冲突经重载 / 另存副本解决后状态栏不再误报、指示器点击恢复有效。

### 3.4 #170 文件监听重载决策竞态

**方案**：`useFileWatcher` 在做重载决策前 flush 发布防抖，弹窗后再复核 dirty 状态，消除「丢编辑」与「重载失效」两类竞态。PR 评审追加项：冲突流读盘往返后**再次 flush**，把 `localContent` 收进尾部输入。

### 3.5 #186 冲突对话框层级与键盘可达性

冲突对话框原本层级低于全局搜索 / 快捷键面板会被遮挡，且无 Esc 关闭与打开时的焦点管理。本版一并补齐。

## 4. 编辑器与查找：增量化与卸载安全

涉及 issue：#151、#152、#178、#185、#192、#172、#173、#174

### 4.1 #178 空替换串崩溃

**根因**：替换串为空时走 `schema.text("")`，ProseMirror 抛 `RangeError: Empty text nodes are not allowed`。

**方案**：空串改走 `tr.delete`；`replaceCurrent` / `replaceAll` 改为**显式接收替换串参数**，不再隐式依赖面板状态。

### 4.2 #185 关闭查找面板后高亮残留

**方案**：`SearchPanel` 卸载时 dispatch `clear`。此前高亮要等切换文件才消失。

### 4.3 #151 查找面板打开时编辑性能劣化

**根因**：`replace` 位于搜索 effect 的依赖中，导致每敲一个字符触发全文重匹配并拽动视口；装饰集每次 transaction 全量重建。

**方案**：`replace` 移出依赖；`SearchOpts` 移除仅面板使用的 `replace` 字段；`DecorationSet` 按 `(matches, current, doc)` 引用缓存，无关 transaction 不再重建。

### 4.4 #192 每键全文重扫 → 增量更新

在 #151 的缓存基础上进一步做**结构性增量**：`searchPlugin` 在 `docChanged` 且为单步事务（典型按键形态）时走增量路径——

1. 变更窗口外的旧匹配区间经 `tr.mapping` 平移到新文档位置；
2. 仅对变更波及的文本节点窗口重扫，局部增删匹配；
3. 装饰集经 `DecorationSet.map` 平移后，移除窗内旧装饰、补入新装饰；
4. 旧匹配整体被删除而坍缩为空区间时直接丢弃，防止 `{n,n}` 幽灵空匹配。

多步事务（如全部替换）回退全量重算以保证正确性。装饰集移入 plugin state（`apply` 持有 `tr` 才能做 mapping），`props` 直接返回稳定引用，使 #151 的按引用缓存语义在新架构下继续成立。新增 8 例增量单测（局部编辑扫描与文档规模解耦、结果与全量重算一致、多步回退全量、窗外当前高亮类不丢失、越界收敛）。

### 4.5 #172 编辑器慢启动被误判为失败（卸载—重建循环）

**根因**：旧的 3 秒超时把「loading 超过阈值」一律当失败，`setFallback(true)` 卸载 `<Milkdown/>`。而 `@milkdown/react` 卸载会对**仍在 `create()` 中的 editor** 调 `destroy()`；随后 `create()` 完成又重新挂载重建。慢启动因此表现为「加载失败闪烁 + 双倍初始化」，且可能反复触发。

**方案**：重构为 `useEditorFallback` 监督器，区分 loading 久置的三种成因：

| 成因 | 判定 | 行为 |
|---|---|---|
| 工厂同步抛错 | `catch` 中 `markFactoryFailed` 显式上报，loading 永不结束 | **立即降级** |
| `create()` 在途（慢启动） | 超阈值但仍在途 | **只亮 slowStart 提示，不卸载** |
| 异步失败 | `loading=false` 后 `getEditor()` 仍为空 | 降级 |

**变异验证**：改回旧的「超时即 `setFallback(true)`」后，对应用例失败。

### 4.6 #173 代码块语言异步加载竞态

快速切换语言时，先发起的加载可能后返回并覆盖最新语言配置。加竞态守卫使**过期结果不覆盖最新语言**。

### 4.7 #174 源码模式卸载快照 scrollTop 现场读取

**根因**：卸载快照时直接读 `view.scrollDOM.scrollTop`，依赖元素仍挂载在 DOM 上。React 卸载时序下该读数不可靠（`clientHeight` 可能为 0，`scrollTop` 被钳制为 0），导致阅读位置丢失。

**方案**：新增 `readDetachSafeScrollMetrics`——`clientHeight > 1` 时取现场读数，否则回退组件内缓存的最近一次有效快照。

## 5. 全局搜索：取消机制、并行化与内存护栏

涉及 issue：#163、#176、#160

### 5.1 #176 命中行整行克隆导致 OOM

**根因**：搜索预览对命中行做**整行克隆**。含内嵌 base64 图片的文档单行可达数 MB，5000 条命中即可 OOM 崩溃。

**方案**：preview 改为命中点附近的**字符级窗口**（前后 120 字符 + 命中片段封顶 200 字符），使预览总量与文档行长解耦、常数级封顶。

### 5.2 #160 5000 条截断对前端不可见

**方案**：返回结构改为 `{ hits, truncated }`，前端状态栏明确提示「已达 5000 条上限，结果已截断」。

**修正误报**：`scan_files` 返回 `exceeded` 标记，**仅在确认存在第 `MAX_TOTAL_HITS+1` 条命中时**才置 `truncated`——命中数恰好 5000 时不再误报截断。

### 5.3 #163 无取消机制、单线程全量扫描

**方案**：

- **代次取消**：引入搜索代次（generation）。代次推进时，在途旧任务在检查点提前退出；面板卸载的 cleanup 发起「空查询 + 新代次」的 fire-and-forget 搜索，让命令入口登记新代次，空查询立即返回，从而使在途扫描尽快退出。
- **减少开销**：目录符号链接确定不跟随后，去掉逐目录 `canonicalize`。
- **并行化**：文件扫描按 CPU 数分片并行，**按片序合并**以保持结果与单线程完全一致的确定性。

## 6. 启动性能：依赖懒加载与存储写入治理

涉及 issue：#168、#153

### 6.1 #168 Mermaid 与 KaTeX 静态导入

**根因**：`mermaid-view.ts` 与 `math.ts` 在模块顶层静态 import，应用启动即加载约 1.1MB（gzip）与编辑器无关的大依赖，即使文档里根本没有图表或公式。

**方案**：改为**首次遇到对应节点才动态 `import()`**，并 Promise 缓存复用（沿用 `code-block-view` 的语言懒加载范式）。

- **Mermaid**：约 3.1MB vendor 不再进入启动加载图；渲染结果缓存命中的图表连模块都不需要加载。
- **KaTeX**：JS + 样式 + mhchem 在首次渲染公式节点时一并动态加载；render 回调以 `seq` 守卫丢弃过期结果（节点值快速变化时只渲染最新一次）。

**验证**：新增 `mermaid-lazy-load` / `math-lazy-load` 单测，用动态 import 计数 + 模块工厂调用计数验证「懒」「单次加载/初始化」「缓存命中跳过渲染」「seq 守卫」。

### 6.2 #153 DeletedSnapshots 每 2 秒重写全部快照

**根因**：健康探测定时器每 2 秒 `JSON.stringify` 整个快照列表写入 localStorage，**即使列表为空**也在写。

**方案**：

- 健康探测改为只写 **1 字节哨兵键**，不再序列化整个列表。
- 区块刷新改为**事件驱动**：挂载时读一次 + 同窗口变更事件 + 跨窗口 `storage` 事件。
- 删除 2 秒轮询定时器，空列表时开销为零。

## 7. 多窗口与工作台一致性

涉及 issue：#147、#150、#165、#167、#187

### 7.1 #147 单实例 open-file 固定发往主窗口

**根因**：单实例回调硬编码主窗口 label。主窗口被关闭后，`emit` 落到不存在的窗口上，双击 `.md` 文件静默失效且不聚焦。

**方案**：新增 `pick_open_file_target_label`，从**存活窗口**中选择目标（主窗口存活优先，否则取字典序首个），并对目标窗口执行 `unminimize` + `set_focus`；emit 失败显式 `eprintln` 而非静默。前端 `useStartupFile` 同步重构：所有窗口（含派生窗口）都注册 open-file 监听，主窗口负责拉取 pending，派生窗口打开自身路径。

### 7.2 #150 另存为到已打开路径产生重复 tab

**根因**：未命名草稿另存为时，从取到对话框路径到构造 `nextTabs` 之间**没有重复路径校验**，草稿被直接改名为已存在的 path。后果是静默数据错乱：TabsBar key 重复、按 path `find`/`filter` 的操作写错项、关闭时同时删掉两个 tab。

**方案**：写盘前检测目标路径是否已有「其他」tab（排除正在保存的自身）。命中则走合并路径——

- 草稿内容写入目标文件；
- 并入已有 tab 并关闭草稿、激活目标；
- 目标 tab 有未保存内容时先经 `ask` 确认，用户拒绝则**双方原样保留**；
- **写盘窗口期草稿又新增编辑时，保留草稿不丢弃新编辑**（遵循原则 1：宁可多留，不可丢数据）。

### 7.3 #165 多窗口 localStorage 后写覆盖先写

**方案**：新增 `storageSync` 模块，为 `recents` / `bookmarks` / `expandedDirs` 三个持久化 key 注册原生 `storage` 事件，他窗口写入后本窗口立即重读合并，与既有 `settings` / `theme` / `shortcuts` 的模式一致；删除快照 key 的跨窗口变更同样经 `storage` 事件刷新。

### 7.4 #167 侧边栏折叠状态不记忆 + 低窗口文件树被挤没

折叠状态持久化记忆，并修复低窗口高度下三区块把文件树完全挤没的问题。

### 7.5 #187 激活的 tab 不滚入视野

`TabsBar` 按 path 登记 tab 元素，监听 `activeTabPath` 变化执行 `scrollIntoView({ inline: "nearest", block: "nearest" })`，同时让此前被隐藏的滚动条可见。

## 8. 崩溃兜底与可访问性

涉及 issue：#171、#188

### 8.1 #171 全局崩溃兜底过于激进

**根因**：全局 error / unhandledrejection 兜底不做分类，良性错误也会把整个应用替换成**永久崩溃页**，用户只能重启。

**方案**：新增 `src/lib/crash-guard.ts`，以纯函数 `isBenignGlobalError` 做分类：

| 错误类别 | 处理 |
|---|---|
| `ResizeObserver loop` 噪音 | 过滤 |
| 空 message / 跨域 `Script error` | 过滤 |
| 未捕获 promise rejection | **只记日志，不替换界面**（异步链断裂多数可恢复） |
| 其余致命错误 | 触发崩溃页 |

`useStartupFile` 的 `take_pending_file` 补 `.catch`，启动不再因单个命令异常直接进崩溃页。

### 8.2 #188 键盘可操作性与 ARIA 语义（5 处）

| 位置 | 问题 | 修复 |
|---|---|---|
| 全局搜索「区分大小写 / 正则」开关 | checkbox `display:none`，键盘完全不可达 | 改 `visually-hidden`（保留原生聚焦与切换），补 `:focus-visible` 焦点环 |
| 冲突态保存指示器 | `role=button` 的 `<span>`，Tab 不可聚焦、Enter/Space 无原生触发 | 改为真实 `<button>`，补按钮样式重置与焦点环 |
| 标签页 | 无 `tablist`/`tab` 语义，方向键无法切换，关闭按钮 `opacity:0` 时键盘聚焦不可见 | 补 `role`/`aria-selected`/roving `tabIndex`，Enter/Space 激活，方向键与 Home/End 切换并移焦，`.tab-close` 补 `:focus-within`/`:focus-visible` 显形 |
| 菜单系统（3 个下拉 + 2 个右键） | 打开后不聚焦首项、方向键无法导航 | 新增 `useMenuA11y` hook；补 `role=menuitem`/`role=menu`、`aria-haspopup`/`aria-expanded`；顶栏任一菜单打开时 Esc 统一关闭 |
| 文件树 | `role=treeitem` 的 `aria-level` 运行时全为 `null`，屏幕阅读器无法感知层级 | 补 `aria-level={depth+1}` |

**防回退**：新增 4 个组件测试文件 + TabsBar 键盘用例，并加**源级静态断言**（`aria-a11y-static`，直接读 CSS/TSX），防止 `display:none`、`opacity:0` 这类纯视觉修复被后续改动反向回退。

**变异验证**：关闭菜单聚焦首项 → 菜单用例失败；禁用 Enter/Space → TabsBar 用例失败；移除 `aria-level` → 文件树用例失败；指示器回退为 `<span>` → tagName 用例失败；`gs-toggle` 改回 `display:none` → 静态用例失败；还原后全部恢复。

## 9. 安全加固

涉及 issue：#162

**根因**：`tauri.conf.json` 的 `assetProtocol.scope` 含 `$DATA/**` 与 `$TEMP/**`。Tauri v2.11 中 `$DATA` 展开为通用数据目录（Windows 上即**整个 `%APPDATA%`，覆盖所有应用**）、`$TEMP` 为系统临时目录——静态放行面远超图片加载所需。

**方案**：

- 静态 scope 收缩为 `$APPDATA/**` + `$APPLOCALDATA/**`。图片实际存放于文档同目录 `assets/`，经运行时 `allow_asset_dir` 按需放行，静态 scope 只需兜底应用自身目录。
- 远程图片（http/https）经 `image-node-view` 渲染 `<img>` 时加 `referrerpolicy="no-referrer"`，避免文档被打开时把页面上下文经 Referer 头泄露给外部图床（跟踪像素场景）。
- CSP `img-src` 保留 `https:`，以维持「文档内远程图片可显示」这一既有功能（收紧为开关属于后续可选加固，不在本版强行改变行为）。

**变异验证**：scope 加回 `$DATA` → `asset-scope-security` 用例失败；移除 `referrerpolicy` → `image-node-view-referrer` 用例失败。

## 10. 交互细节

涉及 issue：#158、#184

### 10.1 #158 文件树非 Markdown 行右键菜单无法唤起

**根因**：原生 `disabled` 表单控件会被 Chromium/WebView2 **抑制 `contextmenu` 等鼠标事件**。txt/png 等非 md 文件因此失去了右键菜单这个唯一可用的操作入口（重命名 / 删除 / 复制路径）。

**方案**：改用 `aria-disabled` 表达禁用态（保留视觉弱化类名），在 `onClick` 内拦截打开动作，`contextmenu` 事件恢复可达。

### 10.2 #184 图片右键菜单泄漏与叠加

**方案**：实例持有当前菜单与 document 级 close 监听引用，新增**幂等** `closeContextMenu` 统一清理（DOM + 监听 + 单例游标）；模块级单例保证同一时间只有一份菜单，打开新菜单先关旧菜单（含其他图片节点的残留）；`destroy()` 清理打开中的菜单；`setTimeout` 注册的监听加存活守卫。
