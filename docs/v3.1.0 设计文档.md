## 1. 版本定位

v3.0.0 主版本质量攻坚后收到两份实测反馈，分别落在**性能热路径**与**回归门禁可信度**上：

1. 120Hz 高刷屏用户在万行级复杂文档（大量代码块 / Mermaid / 表格 / 图片）上滚动只能获得 ~60-68fps 观感——这是 v2.8.0（#136 修复，PR #139 落地）起所有版本持续存在的体验退化，用户在 60Hz 设备上因帧预算翻倍而不易察觉。
2. #136 门禁套件中用例 B 存在高失败率 flaky（main 33% 首跑失败），CI 的 `retries: 2` 长期掩盖，本地无重试的全量跑批呈非确定性失败——削弱了防复发信号。

两者本质都是「机制与场景不匹配」：#212 是**正确性机制选错了执行时机**（锚点缓存放进了滚动热路径），#214 是**测试夹具没对齐过渡完成时机**（退出收敛未完成就写滚动）。本版本对前者做机制换血，对后者做夹具收敛。

## 2. #212 万行复杂文档滚动掉帧：锚点采样时机前移

### 2.1 背景：cacheTopPos 为什么存在

模式切换滚动恢复（#136 / PR #139）需要「视口顶部内容对应的 PM 位置」（内容锚点）作为跨容器（WYSIWYG ↔ 源码 CM）保持阅读位置的依据。而切换进入源码模式的 `useLayoutEffect` 在 DOM 已 `display:none` 之后运行——此时 `posAtCoords` / `scrollHeight` 的现场读取全部被钳 0，几何不可靠。因此 #139 用「滚动监听持续缓存视口顶锚点」来保证切换瞬间有值（缓存三件套：scrollTop / scrollHeight / topPos），并配 B1 rAF 合帧 + 切换时 flush 兜底（commit 32a3519）。

### 2.2 根因（issue 已 profiling + 版本对照确认）

滚动监听每帧（rAF 合帧）执行 `cacheTopPos()`：

1. `view.posAtCoords()` 内部调用 `elementFromPoint`。滚动过程中懒挂载 CM6 代码块（rootMargin 200px 预载）、Mermaid 渲染、图片加载持续脏化布局，导致**几乎每帧强制同步重排整篇文档**（实测单次 6~7ms、完全脏化 32ms；120Hz 预算 8.33ms 仅此一项即耗尽）。
2. 命中不透明 NodeView（代码块 / 表格）时 `$pos.depth === 0` 进入 `blockStartAtTop` 二分（布局干净时 <0.1ms，次要）。

性能证据（issue 自带 trace）：`Editor.tsx` cacheTopPos 路径 378 次调用共 2,861ms（median 7.40ms）；HitTest 764 次中 2,569ms（96%）归属该路径。对照组：同 DOM 规模的纯文本大文档稳定 8.3ms/帧——排除 DOM 数量因素，回归由复杂内容结构 + 每帧几何采样组合触发。

### 2.3 方案决策：挑战 Suggested Direction 首选

Issue 首选「缓存几何 + scrollTop 二分」（沿用 outline-tracker v2.3.3 思路），备选「采样时机前移」。**本实现采用备选方向（采样前移）**，理由（PR 正文有完整论证）：

| 维度 | 首选：块顶缓存 + scrollTop 二分 | 本方案：采样时机前移 |
|---|---|---|
| 竞争场景（滚动在途立即切换，验收硬性） | 块顶缓存被懒挂载 / 图片 / Mermaid 高度变化弄陈旧 → 二分锚点漂移，踩 #136 红线 | 采样即消费瞬间的现场几何，必然新鲜 |
| 滚动路径成本 | 仍读 scrollTop + 缓存失效检测 | **零几何读取** |
| 缓存维护 | 3614 块批量 rect 重建（单次 32ms 级）+ 失效条件维护（outline-tracker v2.3.4 有同款失效检测 bug 前科） | 无缓存维护 |
| 质量红线 | — | 非 debounce 降频：采样点在消费时刻，锚点必然新鲜（B1 flush 语义强化版） |

**可行性时序论证**：切换由 click/keydown 离散事件触发，React 18 对离散事件**同步 flush**；采样放在 `setTabSourceMode`（store action）内、`set()` 之前执行——此刻 `.md-editor-wysiwyg` 尚未 `display:none`，`posAtCoords`/`scrollHeight` 现场读可靠；采样与切换 layoutEffect 消费之间只隔一次同步渲染，滚动事件（连续事件）无法插入其间。全部切换入口（顶栏按钮 / SplitPane / 全局快捷键 / 解析失败回退）汇聚于 `setTabSourceMode` 单一咽喉，一处收口全覆盖。

### 2.4 实现

**新增 `src/lib/wysiwyg-anchor-sampler.ts`**（注册表，模式同 `source-mode-scroll.ts`）：

- `registerWysiwygAnchorSampler(filePath, sampler)` / `unregister` / `runWysiwygAnchorSampler(filePath)`——采样器同步执行且 catch 包裹，失败不阻断切换。

**`src/components/Editor/Editor.tsx`**：

- 删除滚动监听 rAF 合帧采样与 B1 flush 机制（`flushWysiwygTopPosRef`）。
- 采样器 `sampleAnchor`（原 `cacheTopPos` 逻辑 + `blockStartAtTop` 二分原样保留，锚点语义与 #139 完全一致）注册到注册表，执行时机三处：编辑器就绪初始一次、切换指令触发（store 经注册表调用）、滚动停歇 150ms 后防御性保鲜。
- **可见性守卫**：`scrollEl.isConnected && clientHeight > 0` 才采样——源码模式激活中容器塌陷（`clientHeight=0`）时跳过，防止缓存被污染成塌陷读数（scrollTop=0 / scrollHeight≈0）。
- 滚动路径保留的监听器只做停歇 debounce 调度，无任何几何读取。

**`src/store/workspace/tabs.ts`**：

- `setTabSourceMode` 仅「WYSIWYG → 源码」方向翻转前同步执行采样器；已处于源码模式（解析失败回退重复置位）跳过——此时容器已塌陷，采样无意义且有污染风险。

**p99 尖刺治理（次要项，达标验收第 2 条所需）**：

- `outline-tracker.ts`：失效检测（scrollHeight/clientWidth 读取会强制布局）与 `rebuildHeadingTops`（425 标题批量 rect，trace 单次 27ms）从滚动采样路径移到**滚动停歇 200ms 后**的 `refreshGeometryAndSample`；滚动帧采样保持纯二分（向下滚动时视口上方内容文档内位置不变，缓存仍准确，停歇后 150ms 内校正）。
- `code-block-view.ts`：IO 回调只入队（不再立即 `initCodeMirror`），静态 drainer 在「250ms 无滚动」让位后 rAF **每帧最多挂载 1 个** CM6 实例——消除同帧批量挂载的 25~75ms 帧尖刺；占位 `<pre>` 等高（v2.3.4 设计），挂载前后视觉零跳变。`destroy` 时从队列移除，drainer 以 `isConnected` 守卫跳过等待期间被移除的节点。暴露测试接缝 `flushMountQueueForTests` / `resetMountQueueForTests`。

### 2.5 验证

**E2E 新增竞争场景回归（issue 硬性要求）** `tests/e2e/source-mode-scroll-race.spec.ts`：

- 万行级 + 1200 代码块文档（mock 文件系统预置，绕开 `insertText` 对 350KB 文本的输入瓶颈——注入必须带 `.ts` 扩展的模块路径，否则 Vite dev 生成第二份模块实例、注入不生效）；
- C1：rAF 连续滚动 30 帧（240px/帧）**不停稳**、最后一帧内同步点击切换 → 断言源码侧视口顶部内容与切换瞬间 WYSIWYG 视口顶部内容一致（内容锚点级断言，±2 节容差）；C2：视口比例不坍缩 / 不钳底（对照）。
- 现有 #136 门禁均「停稳后切换」，此用例补齐滚动在途切换窗口。

**性能复测**（本机 headless 60Hz，万行 1200 代码块文档，rAF 25px/帧 × 360 帧）：

| 指标 | 修复后 |
|---|---|
| median | 16.7ms（满 vsync） |
| p90 | 16.7ms |
| max | 33.4ms（个别 vsync 漏帧量化值） |
| 超 2×median 帧数 | 0 |

对照 issue 基线：v3.0.0 @120Hz median 16.6ms（掉帧一半）。120Hz 精确复测请在 120Hz 开发机按 issue 方法学复核（验收 1/2/3）。

**门禁**：source-mode 全门禁 15/15（A/A2/B/B2/B3 + 混排/表格 + 新增 C1/C2）；全量 E2E 171/171；单测 760/760（新增注册表 11 例 + code-block 批次化 4 例 + outline 新契约 3 例更新）；`tsc` 0 错。

## 3. #214 #136 门禁用例 B 首跑 flaky：夹具收敛

### 3.1 根因（已复现确认，非 suspected）

**复现**（main，`repeat-each=10 --workers=1`）：1/10 首跑失败，前置断言 `ratio(pmBefore) > 0.9` 收到 **0.004**。

机制链：

1. `buildLongDocInWysiwyg`（用例 A/B/A2/B2/B3 共享 fixture）在文档**顶部**进入源码模式 → CM 灌入 300 节长文 → 退出回 WYSIWYG；
2. #136 退出过渡的 settle 收敛循环（最长 30 帧 rAF）按「进入前锚点（文档顶部）」持续校正滚动——模式切换恢复位置的既定行为；
3. fixture 退出后仅 `waitForFunction(scrollHeight >= 10_000)` 等布局撑起，**不等 settle 收敛**（scrollHeight 达阈值时 settle 可能仍在途）；
4. 用例 B 紧接着 `scrollTop = scrollHeight` 滚到底——若赋值落在 settle 结束前，剩余收敛帧把 scrollTop 拽回顶部 → 比例断言失败。

用例 A 的退出路径显式调 `waitScrollConverged`；共享 fixture 漏了这一步。竞争窗口随渲染 / CI 速度开合，呈非确定性。

### 3.2 修复

`buildLongDocInWysiwyg` 退出源码模式后，用 `waitScrollConverged(page, ".editor-scroll", 15_000)` 替换仅看 scrollHeight 的 `waitForFunction`——scrollTop + scrollHeight 连续 3 次稳定（≈300-500ms），同时覆盖「过渡 settle 收敛」与「布局撑起」。

**产品代码不改动**（对 issue 方向 2 的判定）：settle 循环有 30 帧上限 + `<1px` 收敛即止，其覆盖窗口是模式切换过渡的既定行为；引入「外部滚动中止 settle」新语义有 #136 恢复语义回归风险，超出本 flaky 范畴，应单独评估。

### 3.3 验证

用例 B `repeat-each=20` → **20/20**（修复前 1/10 失败）；source-mode 门禁系列 15/15；全量 E2E 171/171 无 retries 下无 flaky。

flaky 为非确定性缺陷，无法用确定性断言锁定；回归保障 = fixture 固定走 `waitScrollConverged`（与用例 A 一致的既定路径）+ 周期性 `repeat-each` 抽检。
